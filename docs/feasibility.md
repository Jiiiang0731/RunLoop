## 1. 项目目标回顾

RunLoop（环跑）是面向马拉松训练者的手机跑步应用。核心功能不是计时，而是：**用户输入目标距离（如 15km），应用在当前位置附近自动生成一条尽可能接近目标距离、起终点闭合、尽量经过适合跑步道路的环形路线**，并提供预览、导航、GPS 运动记录与历史统计。

最终交付：可安装到 Android 手机的 APK + 完整源码 + 文档 + 测试报告。

## 3. 地图服务选型结论

**首版主方案：高德开放平台（AMap）。**

依据（均已真实调用验证，详见 `docs/map_api_research.md`）：

| 能力 | 接口 | 实测结果 |
| --- | --- | --- |
| 地址↔坐标 | `/v3/geocode/geo` | ✅ 0.21s |
| 步行路径规划 | `/v3/direction/walking` | ✅ 返回 distance/duration/steps/polyline |
| 驾车路径规划 | `/v3/direction/driving` | ✅（备选/参考） |
| 骑行路径规划 | `/v3/direction/bicycle` | ❌ `infocode=10002 SERVICE_NOT_AVAILABLE`（本 Key 未开通） |
| 坐标转换 | `/v3/assistant/coordinate/convert` | ✅ GPS(WGS-84)→GCJ-02 |

**高德没有「输入 15 公里直接返回闭合环线」的接口**，因此必须自研环线生成算法（§4），用步行路径规划分段计算真实道路长度。

**备选方案（OSM 生态 GraphHopper/Valhalla）**：仅在后续需要「严格避免主干道/获取更多道路属性/离线部署」时评估。当前高德在国内道路数据完整度与中文导航指令上有明显优势，且本次 Key 已可用，故不切换。结论以实测为准，不因产品名作判断。

## 4. 环线生成算法设计（已通过阶段 1 最小验证）

### 4.1 算法骨架

```
控制点生成 → 分段步行路径规划 → 闭环连接 → 距离校准 → 输出候选
```

1. 以用户选定起点为中心，估算环半径 `R = 目标距离 / (2π × 绕行系数)`（城市步行绕行系数实测 ≈ 1.7，用于加速收敛）。
2. 在半径 R 的圆上生成 M 个控制点（角度与半径带随机抖动，由 `seed` 决定）。
3. 依次对「起点→控制点1→…→控制点M→起点」调用高德步行路径规划，**距离一律取 API 返回的真实道路 `distance`，绝不用直线距离**。
4. 拼接各段折线形成闭环；闭环误差 = 末点与首点的直线距离。
5. 若总距离超差，按比例缩放 R 迭代（带阻尼），直至进入目标 ±500m（尽量 ±300m）。
6. 不同 `seed` 产出不同环线（供 1–3 个候选）。

### 4.2 阶段 1 实测结果（目标 15000m，上海世纪公园起点，M=10）

| 种子 | 总距离 | 误差 | 闭合误差 | 分段数 | API 调用 | 耗时 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 15274 m | +274 m | 0.7 m | 11 | 22 | 7.0 s |
| 2 | 14678 m | −322 m | 0.7 m | 11 | 33 | 10.9 s |
| 3 | 15185 m | +185 m | 0.7 m | 11 | 11 | 5.1 s |

- 全部落在验收要求 14.5–15.5 km 内，闭合误差远小于 50m。
- 折线长度交叉校验：polyline 计算长度与 API 距离之和偏差 ≤1%（见测试报告），证明以 API 距离为准可靠。
- 3 个候选合计 66 次调用、23.0s；单候选 5–11s，基本满足「10 秒内」目标（可通过并行/更优初始 R 进一步压缩）。
- 随机种子确实改变路线几何（不同 polyline 与距离）。

### 4.3 阶段 1 未覆盖、阶段 2 需补齐

- 路线评分（距离误差/闭合/重复路段/连续性/公园绿道覆盖等独立评分模块）。
- 重复路段检测与消除（当前最短路径连接会在少数路段出现小段折返）。
- 起点搜索（500m–1km 范围内选点）、公园/绿道优先。
- 失败与无法闭合的完整处理策略（本阶段 110+66 次调用全部成功，未触发异常分支）。

## 5. 坐标系处理规范（重要）

- **高德（GCJ-02）**：所有地图展示、路径规划输入输出、折线坐标均为 GCJ-02。
- **手机 GPS（WGS-84）**：定位原始坐标为 WGS-84。
- **规范**：内部统一「展示/规划用 GCJ-02，定位原始值保留 WGS-84」，进入地图或规划前执行 `WGS-84 → GCJ-02` 转换。
- 转换途径（均已验证可用）：
  1. 高德 `/v3/assistant/coordinate/convert?coordsys=gps`（在线，批量有限制）；
  2. 开源 GCJ-02 转换公式（`eviltransform`/`coordtransform`，可离线在端内执行，推荐用于高频 GPS 点）。
- 严禁混用坐标系，否则定位、路线叠加、导航均会偏移数百米。

## 6. Android 权限与后台 GPS 方案（阶段 3/4 落实）

计划（需真机逐一验证，不能假设后台必然可用）：

1. 运行时权限：`ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`。
2. Android 10+ 后台定位：`ACCESS_BACKGROUND_LOCATION`，需引导用户授予「始终允许」。
3. 前台服务：跑步中启用 `foregroundServiceType="location"`（Android 14+ 需显式声明 `FOREGROUND_SERVICE_LOCATION`），并配常驻通知。
4. Android 13+ 通知权限：`POST_NOTIFICATIONS`。
5. 锁屏/退后台持续记录：采用 `flutter_background_geolocation`（或 geolocator + 前台服务组合），并针对华为/小米/OPPO 等厂商的电池白名单做引导。
6. GPS 漂移/跳点：距离阈值 + 精度过滤，避免把异常跳点累计为跑距。

这些必须在真实 Android 设备或可靠模拟环境中测试，作为阶段 4 的验收项。

## 10. 现有 API 可直接利用 vs 需自研

**直接利用高德 API**：地理编码、步行/驾车路径规划、坐标转换、地图 SDK 渲染、外部导航跳转。

**必须自研**：闭合环线骨架生成、距离校准迭代、闭环检查、路线评分、重复路段检测、偏航检测、GPS 轨迹滤波、跑量统计、RPE/备注等。

**关键判断**：高德只提供「两点间路径」，不提供「按距离闭环」，因此本项目核心价值正是自研的环线生成与校准层。
