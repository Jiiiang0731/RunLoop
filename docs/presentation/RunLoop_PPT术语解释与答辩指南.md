# RunLoop PPT 术语解释与答辩指南

> 配套文件：`dist/final/RunLoop_项目汇报_最终版.pptx`
> 用途：帮助汇报人理解 PPT 中的技术名词，并准备老师可能追问的问题。
> 原则：PPT 只保留必要技术名称，详细解释放在本文件和演讲者备注中。

## 一、30 秒项目介绍（可直接背）

RunLoop（环跑）是一个面向真实跑步场景的 Android 应用。用户输入目标距离，系统会调用高德地图的真实步行道路数据，生成一条从起点出发、最后回到起点的闭合跑步路线；跑步过程中提供地图、GPS 记录和语音导航，结束后可以查看历史记录。

项目使用 Flutter 开发手机端，Python/Flask 编写路线规划后端，通过 Tailscale 私有网络让手机在户外也能访问自己电脑上的后端。目前应用已经过用户主要真机测试，整体运行正常；后续重点继续优化长距离路线生成速度和偏航后的前向重规划。

## 二、术语表

### 1. Flutter

- 中文名称：Flutter 跨平台界面框架
- 英文名称：Flutter
- 通俗解释：一套用同一份代码开发 Android 和 iOS 界面的工具。界面像搭积木一样由各种组件拼出来。
- 在 RunLoop 中的作用：整个手机 App 的页面、地图容器、按钮、列表和交互都用 Flutter 实现。
- 口语回答：Flutter 是 Google 的跨平台界面框架，我用它写 RunLoop 的手机端，一份代码可以同时考虑 Android 和以后的 iOS。

### 2. Dart

- 中文名称：Dart 编程语言
- 英文名称：Dart
- 通俗解释：Flutter 使用的编程语言，语法接近 Java/JavaScript，专门为界面和异步操作设计。
- 在 RunLoop 中的作用：`lib/` 目录下的所有 Flutter 代码都是 Dart。
- 口语回答：Dart 是 Flutter 的官方语言，App 的页面逻辑、GPS 记录、语音状态机都是 Dart 写的。

### 3. Android 与 APK

- 中文名称：安卓系统与安卓安装包
- 英文名称：Android / Android Package Kit (APK)
- 通俗解释：Android 是手机操作系统；APK 是安卓应用的安装文件，相当于 Windows 的 `.exe` 安装包。
- 在 RunLoop 中的作用：项目优先发布 Android 版，最终交付 Debug 和 Release 两个 APK。
- 口语回答：Android 是目标手机系统，APK 是安装包；Debug 包用于调试，Release 包用正式签名，可以直接安装测试。

### 4. Python

- 中文名称：Python 编程语言
- 英文名称：Python
- 通俗解释：一种易读的编程语言，常用于后端、数据处理和算法。
- 在 RunLoop 中的作用：`backend/` 里的路线生成、距离校准、评分、偏航重规划都是 Python。
- 口语回答：后端用 Python，因为路线算法需要大量几何计算和快速迭代，Python 开发效率高。

### 5. Flask 与 Waitress

- 中文名称：Flask Web 框架与 Waitress 服务器
- 英文名称：Flask / Waitress
- 通俗解释：Flask 负责定义“访问哪个网址、返回什么数据”；Waitress 负责真正接收网络请求并把 Flask 跑起来。
- 在 RunLoop 中的作用：电脑上的后端通过 Waitress 监听 `127.0.0.1:8000`，Flask 提供 `/api/route/generate`、`/api/route/reroute` 等接口。
- 口语回答：Flask 是后端的 Web 框架，Waitress 是运行它的服务器；手机通过接口请求路线，后端再调用高德。

### 6. API

- 中文名称：应用程序接口
- 英文名称：Application Programming Interface
- 通俗解释：两个程序之间约定好的“点菜方式”。手机按约定发请求，后端按约定返回数据。
- 在 RunLoop 中的作用：手机端调用后端生成路线；后端调用高德 Web Service API 获取真实道路。
- 口语回答：API 就是程序之间的接口。RunLoop 有两层 API：手机调我的后端，后端再调高德地图。

### 7. 高德地图 SDK 与高德 Web Service API

- 中文名称：高德地图开发接口
- 英文名称：AMap SDK / AMap Web Service API
- 通俗解释：高德提供的地图和路线服务。SDK 负责在手机里显示地图和定位；Web Service 负责在服务器端计算真实步行/驾车路线。
- 在 RunLoop 中的作用：手机端用 SDK 显示地图和定位；后端用 Web Service 生成真实道路的路线和步骤。
- 口语回答：高德有两类接口：手机端 SDK 负责地图和定位，后端 Web Service 负责真实道路规划，两者配合使用。

### 8. GPS

- 中文名称：全球定位系统
- 英文名称：Global Positioning System
- 通俗解释：手机通过卫星信号计算自己的经纬度、速度和方向。
- 在 RunLoop 中的作用：跑步记录、路线进度、偏航检测、语音转弯提示都依赖 GPS。
- 口语回答：GPS 提供当前位置和速度；我把 GPS 点投影到规划路线上，算出已跑里程和下一个转弯。

### 9. WGS-84 与 GCJ-02

- 中文名称：两种地图坐标体系
- 英文名称：WGS-84 / GCJ-02
- 通俗解释：WGS-84 是 GPS 原始的全球坐标；GCJ-02 是中国地图服务常用的加密偏移坐标。
- 在 RunLoop 中的作用：手机 GPS 原始点需要转成 GCJ-02，才能和高德地图、路线折线准确对齐。
- 口语回答：手机 GPS 给的是 WGS-84，高德地图用的是 GCJ-02；项目中做了坐标转换，否则定位会整体偏移。

### 10. TTS

- 中文名称：文字转语音
- 英文名称：Text-to-Speech
- 通俗解释：把一段文字交给手机系统，让系统用语音读出来。
- 在 RunLoop 中的作用：播报倒计时、前方转弯、每公里配速、目标完成和偏航提示。
- 口语回答：TTS 是系统自带的文字转语音能力；RunLoop 不额外买语音服务，直接调用手机的中文语音引擎。

### 11. TurnEvent（统一转弯事件）

- 中文名称：统一转弯事件
- 英文名称：TurnEvent
- 通俗解释：把“在路线多少米处、向左还是向右、角度多大、是否可靠”整理成一个统一对象。
- 在 RunLoop 中的作用：地图上的转弯图标、顶部“下一转弯”和语音播报都只读这个对象，保证三者方向一致。
- 口语回答：之前地图和语音各算一套，会出现地图左转、语音右转；我建立了 TurnEvent，让地图、提示和 TTS 使用同一个经过验证的结论。

### 12. Polyline（路线折线）

- 中文名称：折线
- 英文名称：Polyline
- 通俗解释：按顺序排列的一串经纬度点，把相邻点连起来就是地图上的路线。
- 在 RunLoop 中的作用：地图绘制、GPS 投影、转弯里程、方向箭头都基于这条折线。
- 口语回答：折线就是路线的坐标点序列；地图画线和 GPS 进度计算都用同一条折线，避免两套数据对不上。

### 13. RDP（保形折线简化）

- 中文名称：Ramer-Douglas-Peucker 折线简化
- 英文名称：RDP / Ramer-Douglas-Peucker
- 通俗解释：在尽量不改变路线形状的前提下，删掉一些几乎在直线上的多余点。
- 在 RunLoop 中的作用：早期按“隔一个点取一个”会让 1081 米的路线缩成 991 米，裁掉拐角；RDP 保留真实拐角，长度误差约 0.17%。
- 口语回答：RDP 是一种保形简化算法；我用它替代了粗暴的隔点抽稀，保证地图路线和真实道路一致。

### 14. 路线闭环

- 中文名称：闭合路线
- 英文名称：Closed loop
- 通俗解释：从起点出发，最后回到同一个起点，形成一个圈。
- 在 RunLoop 中的作用：用户不需要自己规划返程；闭环误差是起点和终点之间的距离，目标小于 50 米。
- 口语回答：闭环就是起点和终点重合；项目会计算闭合误差，通常控制在 0.6 米以内。

### 15. 控制点

- 中文名称：路线骨架控制点
- 英文名称：Control points
- 通俗解释：先在地图上放几个“必须经过的参考位置”，再让真实道路规划把它们连起来。
- 在 RunLoop 中的作用：控制点决定候选环线的大致形状；1 公里用 6 个点，1.5–3 公里用 8 个点。
- 口语回答：控制点是路线的骨架；我先布点，再逐段调用高德真实步行规划，避免在地图上画直线穿墙。

### 16. 候选路线与候选评分

- 中文名称：多条备选路线与质量评分
- 英文名称：Candidate routes / Candidate scoring
- 通俗解释：一次生成多条可能的环线，再按距离、转弯、重复等指标打分，选最合适的一条。
- 在 RunLoop 中的作用：用户可以看到候选列表；评分综合距离误差、转弯密度、直行比例、重复率和急弯/掉头。
- 口语回答：系统不会只生成一条，而是生成多个候选；评分不是只看距离，还要看转弯多不多、有没有重复路段。

### 17. 距离校准与距离容差

- 中文名称：把路线长度调整到目标距离
- 英文名称：Distance calibration / Tolerance
- 通俗解释：生成的路线可能偏长或偏短，需要调整骨架半径或形状，让真实距离接近用户输入。
- 在 RunLoop 中的作用：±500 米是最大容差，不是目标；内部目标约 5%，1 公里实测约 1030 米。
- 口语回答：容差是“最多能接受多少误差”，不是“随便差 500 米”；1 公里我们希望尽量接近 1 公里。

### 18. 转弯密度、重复率、闭合误差

- 中文名称：路线质量指标
- 英文名称：Turn density / Repetition ratio / Closure error
- 通俗解释：转弯密度是每公里有多少次转弯；重复率是同一段路被走了多少比例；闭合误差是终点离起点多远。
- 在 RunLoop 中的作用：用于比较候选路线质量，避免路线太碎、来回绕或没有真正闭合。
- 口语回答：这三个指标分别衡量“转弯多不多”“有没有走回头路”“有没有真正回到起点”。

### 19. 动态偏航与重规划

- 中文名称：跑偏后的路线重新规划
- 英文名称：Dynamic rerouting
- 通俗解释：发现用户没有按原路线跑，就根据当前位置重新给一条接下来的路线。
- 在 RunLoop 中的作用：检测偏航后停播旧指令，请求后端生成连接段，接入新路线；失败也不结束运动。
- 口语回答：偏航重规划不是让用户回到过去，而是从当前位置重新规划接下来怎么跑。

### 20. 前向重规划、接回点与首段方向

- 中文名称：向前延伸的重规划
- 英文名称：Forward rerouting / Rejoin point / Initial heading
- 通俗解释：接回点是重新接上原路线的位置；首段方向是新路线前几十米是不是顺着用户当前跑的方向。
- 在 RunLoop 中的作用：只从原路线未完成部分选接回点；首段夹角 >90° 或回退 >25 米会被拒绝；无法合理接回时如实提示。
- 口语回答：用户已经跑过路口，就不应该让他掉头回去；系统会优先沿当前方向继续，必要时提示“前方无法合理接回”。

### 21. 前台服务与 WakeLock

- 中文名称：Android 前台服务与唤醒锁
- 英文名称：Foreground service / WakeLock
- 通俗解释：前台服务让 App 在后台继续运行并显示常驻通知；WakeLock 防止 CPU 在锁屏后休眠。
- 在 RunLoop 中的作用：锁屏后继续接收 GPS、计时和播报语音。
- 口语回答：跑步时启动定位型前台服务，并持有 WakeLock，避免锁屏后系统把记录和语音冻结。

### 22. Tailscale、Tailnet、Tailscale Serve、HTTPS、MagicDNS

- 中文名称：私有虚拟组网与加密访问
- 英文名称：Tailscale / Tailnet / Tailscale Serve / HTTPS / MagicDNS
- 通俗解释：Tailscale 把手机和电脑组成一个只有自己设备能加入的私有网络；Tailnet 是这个私有网络；Serve 提供 Tailnet 内的 HTTPS 入口；HTTPS 是加密传输；MagicDNS 是给设备起好记域名的功能。
- 在 RunLoop 中的作用：手机在户外用移动网络也能访问自己电脑上的后端，不需要买云服务器，也不把后端暴露到公网。
- 口语回答：Tailscale 是私有虚拟组网，不是公网服务器；电脑必须开机在线，手机和电脑要登录同一个 Tailnet；不能开启 Funnel 把私人服务公开。

### 23. Git 与 GitHub

- 中文名称：版本控制与代码托管
- 英文名称：Git / GitHub
- 通俗解释：Git 记录每次代码修改，GitHub 是把代码仓库放到网上供他人查看和下载的平台。
- 在 RunLoop 中的作用：保存开发历史、协作和开源发布。
- 口语回答：Git 负责记录版本，GitHub 负责公开代码；提交前会检查不把密钥、签名证书和私人地址上传。

### 24. MIT License

- 中文名称：MIT 开源许可证
- 英文名称：MIT License
- 通俗解释：一种宽松的开源许可证，允许别人使用、修改、分发代码，但必须保留版权声明，并且作者不承担担保责任。
- 在 RunLoop 中的作用：项目根目录的 `LICENSE` 文件，方便其他开发者合法使用和继续开发。
- 口语回答：项目采用 MIT License；它允许别人学习和修改，但不提供安全或使用担保。

### 25. Android SDK、Gradle、SHA-1、Keystore

- 中文名称：安卓构建工具与签名
- 英文名称：Android SDK / Gradle / SHA-1 / Keystore
- 通俗解释：SDK 提供安卓开发工具；Gradle 负责编译打包；SHA-1 是证书指纹，高德 Android Key 需要绑定包名和 SHA-1；Keystore 是 Release 签名证书文件。
- 在 RunLoop 中的作用：构建 Debug/Release APK，并让高德 Android Key 与包名、签名匹配。
- 口语回答：APK 用 Gradle 构建；Release 包使用原有 Keystore 签名；高德 Android Key 绑定了包名和 SHA-1，所以证书不能随意更换。

### 26. 自动化测试、真实 API 测试、真机测试

- 中文名称：三层测试
- 英文名称：Automated tests / Real API tests / Real-device tests
- 通俗解释：自动化测试用代码验证逻辑；真实 API 测试让后端真的调用高德；真机测试是在用户手机上实际跑步。
- 在 RunLoop 中的作用：三层分开报告，避免把“接口返回成功”当成“用户已经听到声音”。
- 口语回答：项目有 209 项 Python、209 项 Flutter 自动化测试；另外做了真实高德 API 回归和用户真机测试，三者分开说明。

### 27. 缓存 TTL 与 QPS 限流

- 中文名称：缓存有效期与每秒请求限制
- 英文名称：TTL / QPS / Rate limiting
- 通俗解释：TTL 是缓存保存多久；QPS 是每秒最多允许发多少请求，超过会被地图服务限流。
- 在 RunLoop 中的作用：后端缓存成功路线、减少重复调用；全局约 3 QPS 限速，避免触发高德 10021 限流。
- 口语回答：重复请求直接复用缓存；高德 Key 有 QPS 上限，所以用令牌桶限速，而不是疯狂并发。

### 28. OSM

- 中文名称：开放街图
- 英文名称：OpenStreetMap (OSM)
- 通俗解释：一个开放的全球地图数据库，可以补充道路、步道等数据。
- 在 RunLoop 中的作用：目前没有接入；后续如果高德数据无法满足照明、步道等需求，可以评估 OSM。
- 口语回答：OSM 是备选数据源，目前没有使用；现有路线仍以高德真实步行道路为准。

## 三、老师可能追问的 15 个问题

### 1. 为什么不用现成的跑步 App？

现成 App 多数是记录轨迹，或者让你自己在地图上画路线；RunLoop 的重点是“输入目标距离，自动生成附近真实闭合路线”，解决的是路线规划问题。

### 2. 为什么用 Flutter？

一套代码可以做 Android，界面开发效率高；项目需要地图、列表、动画和大量自定义布局，Flutter 比较合适。

### 3. 为什么需要 Python 后端，不能全在手机里做？

路线生成需要多次调用高德 Web 服务、做几何计算和候选评分，放在电脑后端便于调试、缓存和更换算法；手机上只负责展示和 GPS。

### 4. 为什么用 Tailscale，不买云服务器？

个人项目用户量小，复用已有电脑成本低；Tailscale 提供私有组网和 HTTPS，不需要把后端暴露到公网。缺点是电脑必须开机在线。

### 5. 电脑关机后还能生成路线吗？

不能。已缓存的路线和 GPS 记录可以离线使用，但生成新路线需要电脑后端在线。这一点在 PPT 和 README 里都明确写了。

### 6. 路线是怎么保证是真实道路的？

不是在地图上画圆或直线，而是把控制点交给高德步行规划，逐段返回真实道路折线和步骤，再拼接、校准和评分。

### 7. 怎么保证左右转不颠倒？

用真实折线的累计里程和几何角差，与高德结构化 action 交叉验证，统一成一个 TurnEvent；地图图标、顶部提示和 TTS 都只消费这个对象。

### 8. 为什么之前会出现“地图左转、语音右转”？

早期地图折线被隔点抽稀，步骤又被错误合并，地图和语音各用一套数据；后来改成保形折线 + 统一 TurnEvent，并加了方向测试。

### 9. 转弯播报为什么会迟？

旧逻辑用步骤里程和固定提前量；现在用真实折线累计里程和配速动态提前量，越过路口 30 米就作废，不再补播过期指令。

### 10. 偏航后为什么不能直接接回最近的点？

最近的点可能在用户身后，会让用户掉头。新逻辑只从未来未完成路段选接回点，并检查首段方向和回退距离；无法前向接回时如实提示。

### 11. “前向重规划”现在完全做好了吗？

还没有。真实道路网络复杂，部分路口/平行道路仍可能需要更智能的方向约束；这是目前继续优化的两个重点之一。

### 12. 1 公里路线真的接近 1 公里吗？

在用户校园起点实测约 1030 米，误差约 3%；±500 米是最大容差，不是目标。不同起点和路网会影响结果。

### 13. 为什么 50 公里还是慢？

50 公里需要大量真实道路请求，受高德 QPS 限制；目前约 143 秒、402 次调用，仍在继续优化候选搜索和缓存。

### 14. 数据安全吗？密钥会进 APK 吗？

高德 Web Service Key 只在电脑后端本地配置，不进 APK；Android SDK Key 只用于地图/定位，绑定包名和 SHA-1；Tailscale 截图中的账号和设备信息已遮挡。

### 15. MIT License 是否等于可以随便用？

MIT 允许使用、修改和分发，但必须保留版权声明，作者不提供担保；跑步路线安全仍需用户自己判断，项目另有免责声明。

## 四、答辩时的表达建议

1. 先讲“为什么做”，再讲“怎么做”，最后讲“做到什么程度、还差什么”。
2. 技术名词第一次出现时用一句话解释，不要堆定义。
3. 不要夸大：没有真机验证的不说“已通过”；没有的数据不说“已覆盖”。
4. 不要把所有技术都说成自己从零实现：Flutter、高德、Tailscale、TTS 都是成熟工具，项目做的是整合、算法和产品设计。
5. 如果老师追问细节，先回答结论，再补一句实现位置，例如“这部分在 backend/route_generator/calibrator.py”。
6. 遇到不确定的问题，可以说明“这个点目前没有实测数据，我的判断是……”，不要编造。

## 五、不要这样说

- 不要说“Tailscale 是云服务器”。
- 不要说“电脑关机后也能生成新路线”。
- 不要说“路线绝对安全”。
- 不要说“锁屏语音已经在所有手机上验证通过”（以用户实际真机测试范围为准）。
- 不要说“AI 自主完成了整个项目”；人是产品决策和验收主体，AI 是分阶段工具。
- 不要说“所有道路数据都覆盖了照明、车流和路宽”；这些数据目前没有。
- 不要说“1 公里一定精确到 1 公里”；只能说实测约 1030 米，存在位置依赖。
