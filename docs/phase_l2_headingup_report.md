# 阶段 L2 补充整改报告：真正的跑步导航视角（Heading-Up Navigation）

日期：2026-11-04 ｜ 触发：用户真机体验反馈「语音基本正常，但地图方向与缩放不符合导航要求」｜ 基线：`c8bec16`

---

## 1. 真机反馈 → 根因分析（为什么上一版不对）

| 用户观察 | 根因 | 本次修复 |
| --- | --- | --- |
| 箭头没有始终指向屏幕正上方，跟着地图转 | 上一版用普通 **AMap Marker** 表达跑者方向（heading-up 时 rotation=0）。真机证实高德 Marker 的 rotateAngle 语义无法保证「屏幕恒朝上」——marker 随地图 bearing 一起旋转，箭头实际指向随地图乱转 | **弃用 Marker 表达方向**：新增屏幕固定 Flutter 组件 `RunnerArrow`，钉在地图区正中央，与相机 bearing 完全解耦（规范三「必要时改成屏幕固定的居中导航组件」） |
| 地图比例不符合跑步导航需求 | 上一版固定 `_runZoom = 17.0`——只能看到大片区域，看不清前方道路/路口 | 默认 **18.5**，设置页提供 18.0/18.5/19.0 三档供真机对比选定；临近转弯自动 +0.2/+0.4；捏合缩放即采纳 |
| 跟随不平滑、不像专业导航 | 相机由 **1Hz** GPS 回调直接驱动，且每次 `moveCamera(animated:true)`（250ms 动画 + 1.5m/2° 死区）→ 每秒一跳 + 动画互相打断 | 新架构 `FollowCamera`：**目标位姿 1Hz 更新、渲染位姿 20Hz 指数插值**、非动画逐帧下发、微米级死区——平移/旋转/缩放全部连续 |

## 2. bearing 正负方向核验（规范一.3：不凭经验写死）

证据链：

1. **插件源码**：`packages/amap_flutter_map/android/.../ConvertUtil.java:164` → `builder.bearing(toFloat(data.get("bearing")))`——Dart 侧 `CameraPosition.bearing` **原样透传**给高德原生 `CameraPosition.Builder.bearing()`，插件不做任何符号变换。
2. **高德原生语义**：bearing =「可视区域指向的方向，从正北顺时针」= **屏幕正上方显示的罗盘方位**。
3. **推论**：`mapBearing = 行进方向(罗盘角)` ⇒ 行进方向出现在屏幕正上方。

用户左转场景验证（北行→西行，规范一.3 的例子）：

| 状态 | 行进方向 | 下发 bearing | 屏幕效果 |
| --- | --- | --- | --- |
| 向北跑 | 0° | 0 | 北在上（= 正常北向图）✓ |
| 左转中 | 0°→270° 连续变化 | 最短弧 0→270（数值上走 −90°） | 地图内容**顺时针**旋转，北方从屏幕上方移到右侧 ✓ |
| 向西跑 | 270° | 270 | 西在上，左转后的道路朝屏幕正上方延伸 ✓ |
| 右转（北→东） | 0°→90° | +90 | 地图内容逆时针转，东来到上方 ✓ |

该场景已固化为单元测试（`follow_camera_test.dart`「用户左转场景」：断言 bearing 走 −90° 短弧且收敛到 270，绝不绕 +270 长弧）。359°→0° 跨越同样走 +1° 短弧（`shortestDelta` 数学在两处复用，测试覆盖）。

## 3. 三原则 → 实现映射

**原则 1：用户位置始终在屏幕正中央。**
- 相机目标 = 最后一个通过 GpsFilter 的真实定位点（与轨迹绘制同源，规范三.6「定位点与 GPS 真实坐标一致」）；
- 20Hz 插值使中心连续跟随（位置时间常数 0.30s：4m/s 配速下视觉滞后 ≈1m，每个新定位点到来立即收敛）；
- `RunnerArrow` 钉在地图区几何中心（`Align(center)`），相机中心=GPS 点 ⇒ 箭头位置=真实定位点；
- 手动平移才会脱离中心（这是用户主动行为），右下角一键回中。

**原则 2：行进方向始终指向屏幕正上方。**
- Heading-Up 跟随：`RunnerArrow.screenRotationDegrees = 0` 恒定——箭头**永远**指屏幕正上，不参与任何地图旋转；
- 北朝上模式：箭头顺时针转到平滑航向（地图不转，箭头转）；航向暂不可得时退化为无方向圆点——宁可不指，绝不错指；
- 箭头是 Flutter 自绘（蓝色导航锥形 + 白描边 + 轻投影，46px 适中尺寸，不遮挡前方道路）；旋转动画按最短弧展开（350°→10° 走 +20°），纯函数 `unwrapNext` 可单测。

**原则 3：地图按实际行进方向旋转（人不动，图动）。**
- 相机 `bearing = 平滑航向`（§2 已验证符号），2D 顶视（tilt 恒 0）；
- 转弯时 bearing 连续变化 → 地图平滑旋转；**双指旋转手势已禁用**（`rotateGesturesEnabled: false`），朝向只由导航逻辑与模式切换按钮控制，杜绝手势与跟随打架。

## 4. 两个地图状态（规范二）

**A. 预览态（倒计时覆盖期间）**——保持 Phase K/J 已验证行为不变：北朝上、整条闭合路线 fit-bounds 构图、起点/终点/距离/沿途地标、路线生长动画（在 `route_candidates_screen` 内，本次未触碰）。

**B. 导航态（GO 时刻自动切换）**：
1. GO 瞬间一次 **800ms 动画**从预览构图飞到导航构图：自动放大到 18.5、跑者居中、对齐出发方向（尚无 GPS 航向时用路线起点切线，起步即朝向正确）；
2. 800ms 后 20Hz 跟随定时器接管（避免动画与逐帧移动互相打断）；
3. 缩放策略（规范二.B「结合下一个路口的距离合理调整」）：
   - 基础档：设置页 18.0/**18.5**/19.0（用户可真机对比后选定并持久化）；
   - 距下一真实高德转弯步骤 <250m → +0.2；<80m → +0.4（看清路口），过后自动回落；
   - 捏合缩放 → 立即采纳为新基础档（跟随不解除）；
   - 全部经 0.9s 慢插值过渡，转弯与缩放不同时抢注意力；
4. z18.5 下高德标准图层自然呈现附近道路、交叉口、建筑与地名（规范二.B#5，无自定义图层裁剪）。

## 5. 行进方向计算（规范四，多源综合仲裁）

`HeadingController.update()` 每帧仲裁（优先级从上到下）：

| 优先 | 源 | 采纳条件 | 平滑 |
| --- | --- | --- | --- |
| 1 | **GPS 运动方向**（高德 course，仅 locationType==1） | 速度 ≥1.2 m/s 且精度 ≤40m（四.1/3：跑动优先用 GPS 实际行进方向；精度差不乱转） | τ=0.8s |
| 2 | **路线切线方向**（窗口化匹配点处规划路线方位角） | 速度 ≥0.4 m/s 且在路线上（四.4：匹配可靠时辅助稳定） | τ=0.8s |
| 3 | **磁力计**（flutter_compass，新增） | **仅静止**（速度 <0.6 m/s）且上两源都不可用——起步前岔路口看图、偏航驻足（四.5：只作辅助，绝不把手机朝向等同跑步方向） | τ=2.0s（更钝，防磁抖） |
| 4 | 冻结 | 以上皆无：原地站立/低速/精度差时**不旋转**（四.2） | — |

- 0°/360° 跨越、连续转弯：最短弧 + 指数插值 + <0.5° 吸附（四.6/7），`HeadingController`（τ0.8）与 `FollowCamera`（τ0.25）**双层平滑**，转弯全程无跳变、无抖振、方向不会转错（四.8）；
- **偏航时**（四.9）：路线切线源自动切断（仅 on-route 提供），地图按 GPS 真实运动方向显示，绝不强制拉回路线视角；回到路线后各源自动恢复；
- 无传感器机型：CompassSource 静默降级（heading 恒 null），主流程零影响。

## 6. 手势让位机制（本次自查发现的额外稳健性修复)

上一版存在隐患：用户平移/捏合过程中，程序化 moveCamera 会与手指「抢相机」。本次：

- `onCameraMove` 流式检测：不在程序动画窗口（GO 800ms/回中 400ms + 250ms 余量）内、且事件位姿偏离最近下发值（目标 >8m 或缩放 >0.25）⇒ 判定用户手势 ⇒ `_gestureHold` 暂停 20Hz 下发；
- `onCameraMoveEnd` 决策：平移 >25m ⇒ 解除跟随（圆点 Marker 显示真实位置 + 回中按钮）；仅缩放变化 ⇒ 采纳新档位继续跟随；
- 回中/切换朝向时清除让位状态，立即吸附模型位姿（防插值走长弧）。

## 9. 如实说明与已知局限

1. **无法在本环境真机截图**：zoom 18/18.5/19 的实际观感对比必须由用户在手机上完成——已做成设置页持久化档位（默认 18.5，即三档中间值），无需重新构建 APK 即可切换对比。
2. **磁力计仅静止辅助**：Android 上 flutter_compass 的 accuracy 字段是硬编码近似值（插件源码注释自述），故不做精度过滤，可靠性完全由「静止门控 + 2s 慢平滑」保证；跑动中永不采纳。若某机型磁力计受干扰，静止时地图朝向可能缓慢偏转——起步跑动 2 步后 GPS course 立即接管纠正。
3. **20Hz 插值的位置显示**是「两个真实定位点之间的连续过渡」，每帧都向最新真实坐标收敛（0.3s 内），与 GPS 真实坐标最大瞬时偏差 ≈ 一个定位间隔的行进距离（≤4m）；轨迹线与匹配仍只用真实点，视觉层从不伪造坐标。
4. **手势判定基于位姿差**（无手势原因回调可用，插件/原生均未暴露）：极端情况下（程序下发与用户手势同帧竞争）可能晚 1-2 帧才让位，表现为轻微顿挫，不会丢跟随状态。
5. 上一版报告的其余部分（语音/分段/倒计时/图标/FGS）本次未触碰，仍然有效；语音链路零改动，真机已验证部分不受影响。
